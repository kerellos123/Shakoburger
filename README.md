# St. Paul the Apostle Family

A church youth meeting management platform: a Flutter mobile app (Android + iOS) for
admins, servants, and youth members, a Firebase backend, and a Next.js admin dashboard.

> **Note:** `index.html` and `Logo.jpg` at the repo root are a pre-existing, unrelated
> project ("Shako Burger") and were left untouched. The app described here lives in
> `mobile/`, `admin/`, and `firebase/`.

## Monorepo layout

```
firebase/   Firestore rules/indexes, Storage rules, Cloud Functions (TypeScript)
mobile/     Flutter app (Android + iOS), clean-architecture feature folders
admin/      Next.js + TypeScript + Tailwind admin dashboard
docs/       Database schema and architecture notes
```

## What's implemented vs. scaffolded

This is a full working foundation, not a finished, polished production app — that's a
multi-week build. Here's the honest split:

**Fully wired end-to-end** (models, Firestore rules, repositories, and screens all
connected to real Firebase data):
- Authentication & role-based routing (admin / servant / member)
- Youth member management (profiles, CRUD, servant assignment)
- Attendance (manual marking, QR self check-in, per-member history)
- Follow-up tracking (auto-updated by a Cloud Function, servant worklist with
  call/visit logging and notes)
- Push notifications (targeted send + Cloud Function fan-out via FCM)
- Admin dashboard: users, meetings, attendance, notifications, reports (with
  Excel/PDF export)

**Scaffolded with real models/repositories/screens, ready to extend** (functionally
correct, but simpler UI/UX than the above — e.g. no rich media players wired up yet):
- Sermons, daily devotionals (favorite + share), Bible quizzes + leaderboard,
  activities with registration, news, spiritual library
- Admin dashboard CRUD pages for the same content types

**Simplified by design:**
- "Verse of the day" is a small built-in rotation (`mobile/lib/features/home/domain/verse_of_the_day.dart`)
  rather than a Firestore collection — swap it for one if editorial control is needed.
- "Announcements" reuses the News feed rather than being a separate content type.
- Reports are precomputed nightly into `reportsCache/{yyyy-mm}` by a Cloud Function
  instead of aggregated live, so they stay fast as the roster grows — see
  `docs/DATABASE_SCHEMA.md`.

## Getting started

### 1. Firebase project

1. Create a Firebase project and enable **Authentication (Email/Password)**,
   **Firestore**, **Storage**, **Cloud Messaging**, and **Cloud Functions** (Blaze plan
   required for functions + scheduled jobs).
2. From `firebase/`:
   ```bash
   npm install -g firebase-tools
   firebase login
   firebase use --add          # select your project
   cd functions && npm install && cd ..
   firebase deploy --only firestore:rules,firestore:indexes,storage,functions
   ```

### 2. Mobile app (Flutter)

The Dart source under `mobile/lib` is complete; native Android/iOS project files are
generated by the Flutter tooling itself rather than hand-written here:

```bash
cd mobile
flutter create .                          # generates android/ and ios/ scaffolding
dart pub global activate flutterfire_cli
flutterfire configure --project=<your-firebase-project-id>   # overwrites firebase_options.dart
flutter pub get
flutter gen-l10n                          # generates AppLocalizations from lib/l10n/*.arb
flutter run
```

### 3. Admin dashboard (Next.js)

```bash
cd admin
cp .env.local.example .env.local          # fill in your Firebase web config + service account JSON
npm install
npm run dev                               # http://localhost:3000
```

The first admin user must be created directly in the Firebase console (Authentication
+ a `users/{uid}` doc with `role: "admin"`) — after that, admins can create every other
user from **Users → Add user**.

## Database schema

See [`docs/DATABASE_SCHEMA.md`](docs/DATABASE_SCHEMA.md) for the full Firestore

## Cloud Functions

| Function | Trigger | Purpose |
|---|---|---|
| `sendNotification` | callable | Validates caller role/scope, fans out FCM push to a target |
| `onNotificationCreated` | Firestore create | Sends push for notifications written directly by other functions |
| `onAttendanceWrite` | Firestore write | Recomputes `followUps/{memberId}`, alerts the servant after 3 consecutive absences |
| `sendBirthdayGreetings` | scheduled (daily) | Notifies members whose birthday is today |
| `onQuizAttemptWritten` | Firestore write | Maintains `leaderboard/{uid}` |
| `rebuildMonthlyReport` | scheduled (nightly) | Rebuilds `reportsCache/{yyyy-mm}` |
| `rebuildReportForPeriod` | callable | Lets an admin force-rebuild a historical month |

## Extra features status

- ✅ Arabic + English (`mobile/lib/l10n`)
- ✅ Dark mode (`mobile/lib/core/theme/app_theme.dart`, follows system by default)
- ✅ QR code attendance (generate in admin/mobile, scan in mobile)
- ✅ Role-based permissions (Firestore rules + in-app routing)
- ⚠️ Offline support: Hive is wired in as a local cache dependency; screen-level
  offline-first sync (write queue, conflict resolution) is not yet implemented —
  Firestore's own offline persistence covers basic reconnect-and-sync out of the box.
- ⚠️ Calendar integration, backup/restore, and certificates are not yet implemented.
